# Сервис учета тренировок

## Назначение

Консольное приложение для учета тренировок. Пользователь может записывать
свои тренировки, отслеживать прогресс, анализировать нагрузку и видеть
динамику результатов. Система помогает структурировать информацию о
выполненных упражнениях, подходах, весах и повторениях.

Приложение позволяет:

- вести справочник упражнений (просмотр, поиск, фильтр по группе мышц);
- работать от имени выбранного пользователя;
- создавать тренировки (кардио и силовые) и отменять их;
- смотреть статистику по тренировкам;
- формировать результат за выбранный период и смотреть его статистику;
- хранить данные между запусками программы в JSON-файлах.

## Целевая аудитория

Люди, которые стремятся к здоровому образу жизни и хотят увеличить свою
спортивную активность.

## Предметная область

Основные объекты предметной области:

- **Пользователь** — тот, кто записывает тренировки;
- **Упражнение** — запись справочника (название, группа мышц);
- **Тренировка** — выполненная пользователем тренировка со списком
  упражнений;
- **Результат за период времени** — тренировки пользователя за выбранный
  период.

Связи между объектами:

```text
User ──< Workout >── WorkoutExercise ──> Exercise
User ──< Result  >── Workout
```

Тренировка принадлежит пользователю и состоит из выполненных упражнений
(каждое со своими подходами, повторениями и весом). Результат принадлежит
пользователю и содержит ссылки на тренировки периода.

Бизнес-правила:

- тренировку нельзя создать без хотя бы одного упражнения;
- дата тренировки не может быть в будущем;
- подходы и повторения не могут быть меньше нуля;
- тип тренировки — только «кардио» или «силовая»;
- конец периода результата не может быть раньше его начала;
- отмена тренировки не удаляет её: объект остаётся в коллекции, а
  отменённая тренировка не учитывается в статистике и результатах.

## Основные классы

### `Exercise` — упражнение (`models/exercises.py`)

Атрибуты: `id`, `name`, `muscle_group`.
Методы: `is_for_muscle_group(group)` — проверка группы мышц;
`__str__()` — строковое представление.

### `User` — пользователь (`models/users.py`)

Атрибуты: `id`, `name`, `registered_at` (дата регистрации).
Методы: `from_data(data)` (`@classmethod`) — создание пользователя из
данных JSON; `__str__()`.

### `WorkoutExercise` — выполненное упражнение (`models/workouts.py`)

Связывает упражнение с результатом его выполнения в тренировке.
Атрибуты: `exercise` (объект `Exercise`), `sets`, `reps`, `weight`.
Методы: `is_valid()` — подходы и повторения не меньше нуля; `tonnage()` —
подходы × повторения × вес; `__str__()`.

### `Workout`, `CardioWorkout`, `StrengthWorkout` — тренировки (`models/workouts.py`)

`Workout` — базовый класс. Атрибуты: `id`, `user` (объект `User`),
`workout_date`, `exercises` (список `WorkoutExercise`), `duration_min`,
`is_cancelled`. Тип тренировки задаётся атрибутом класса `WORKOUT_TYPE`.
Методы: `cancel()` — отмена без удаления; `is_in_period(start, end)`;
`is_valid_date(date)` (`@staticmethod`) — дата не в будущем; `__str__()`.

Подклассы наследуют `Workout` и переопределяют `__str__()`:

- `CardioWorkout` (тип «кардио») — в описании показывает длительность;
- `StrengthWorkout` (тип «силовая») — в описании показывает суммарный
  тоннаж (метод `total_tonnage()`).

Подкласс по типу выбирается функцией `build_workout()`, так что
`create_workout()` и загрузка из JSON работают с любым типом одинаково.

### `Result` — результат за период (`models/results.py`)

Атрибуты: `id`, `user` (объект `User`), `period_start`, `period_end`,
`workouts` (список объектов `Workout`).
Методы: `get_stats()` — статистика по неотменённым тренировкам;
`__str__()`.

## Взаимодействие объектов

Объекты хранят ссылки друг на друга, а не идентификаторы:

```text
workout.user                       → User
workout.exercises[i].exercise      → Exercise
result.user                        → User
result.workouts[i]                 → Workout
```

Поэтому данные связанных объектов доступны напрямую:
`workout.user.name`, `workout.exercises[0].exercise.muscle_group`.
Приложение работает с коллекциями объектов (`list[Exercise]`,
`list[User]`, `list[Workout]`, `list[Result]`), словари предметной области
в `main.py` не используются.

Что стало методом, а что осталось функцией. В методы перенесены операции,
относящиеся к конкретному объекту: проверка правил тренировки, отмена,
статистика результата. Функции обработки коллекций (поиск, фильтрация,
сортировка, создание объектов), загрузка и сохранение данных, а также
ввод данных остались обычными функциями.

## Хранение данных

Данные хранятся в JSON-файлах каталога `data/`:

| Файл | Содержимое |
|---|---|
| `exercises.json` | `id`, `name`, `muscle_group` |
| `users.json` | `id`, `name`, `registered_at` |
| `workouts.json` | `id`, `user_id`, `date`, `type`, `duration_min`, `exercises` (`exercise_id`, `sets`, `reps`, `weight`), `is_cancelled` |
| `results.json` | `id`, `user_id`, `period_start`, `period_end`, `workout_ids` |

В JSON записываются только данные и идентификаторы связанных объектов.
Преобразование выполняет модуль `storage.py`:

- при загрузке данные превращаются в объекты, а по `user_id`,
  `exercise_id`, `workout_ids` находятся и подставляются связанные объекты;
- при сохранении ссылки на объекты превращаются обратно в идентификаторы.

Если связанный объект не найден (например, нет пользователя с нужным
`user_id`), запись пропускается и выводится предупреждение. Отсутствующий
или повреждённый файл не приводит к аварийному завершению: загружается
пустая коллекция. Данные сохраняются сразу после каждого изменения.

| `tests/` | автоматизированные тесты |

## Запуск программы

Установка зависимостей:

```text
pip install -r requirements.txt
```

Запуск (из каталога проекта):

```text
python main.py
```

При запуске выбирается пользователь с `id=1`; сменить пользователя можно
в меню (пункт 14).

## Тестирование

```text
pytest -v
```

Тесты проверяют:

- создание объектов `Exercise`, `User`, `WorkoutExercise`, `Workout`,
  `Result`, их атрибуты и `__str__`;
- методы классов, включая `from_data()` и `is_valid_date()`;
- выбор подкласса тренировки по типу и различие их `__str__`;
- бизнес-правила: даты, пустые тренировки, отрицательные значения,
  неизвестный тип;
- связи объектов (`workout.user is user`);
- отмену тренировки без удаления и её влияние на статистику и результаты;
- функции поиска, фильтрации, сортировки и фильтрацию по пользователю;
- сохранение и загрузку JSON: восстановление связей между объектами,
  пропуск записей с отсутствующими объектами, повреждённые и отсутствующие
  файлы.

Линтер:


```text

```

Проверка форматирования без изменения файлов:


(`max-line-length = 88`, отключены правила `E203` и `W503`, которые
конфликтуют с форматированием `black`).
